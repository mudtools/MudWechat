# Mud.Wechat.OpenPlatform.DataModels

微信开放平台「第三方平台（component）」SDK **数据模型包**（纯 DTO）——官方接口出入参模型（**53** 个
`[HttpJsonSerializable]` 类型），2026-10 由 `Mud.Wechat.OpenPlatform.Abstractions` 拆包独立交付。

> 本线形态差异（有意设计，勿「顺手对齐」）：`Mud.Wechat.OpenPlatform.Abstractions` **不引用本包**——
> 主包（`Mud.Wechat.OpenPlatform`）同时引两者，模型面经主包传递可见。TFM 为 `net6.0;net8.0;net10.0`
> 三档（无 netstandard2.0，与线内其它两工程同款收窄：组件 `AddMudHttpClient` 的最小面）。

## 内容

- **域 DTO**（4 个域目录，共 **53** 个 `[HttpJsonSerializable]` 类型，均标注 `SerializerClassName`）：
  - `Component/` —— component 凭证链核心（预授权码 / `api_query_auth` / `api_authorizer_token` 出入参、
    授权方账号与权限集、隐私接口配置等）
  - `Account/` —— 授权方账号信息模型
  - `OpenAccount/` —— 开放账号（unionid 体系）模型
  - `Sns/` —— 网页授权（OAuth2 / snsapi）模型
- **响应基底**（`OpenPlatformResponse.cs`）：实现叶层判错契约 `IWechatApiResponse`
  （`ErrorCode` 缺省 `0` ⇒ 成功），供跨产品线单点判错与异常判定器复用。
- **`Generated/`**（5 个上下文文件：`Common` / `Account` / `Component` / `OpenAccount` / `Sns`）：
  由 `scripts/GenerateJsonContext.ps1`（`mud-jsonctx`）按标注生成的 AOT 源序列化上下文
  （`<auto-generated>`，勿手改），禁止运行时反射序列化。

## 用法

DTO 是纯数据面：宿主只负责填字段，序列化由声明式客户端经源生成 `JsonTypeInfo` 完成。
模型改动同批跑 `AddHttpJsonSerializable.ps1` + `GenerateJsonContext.ps1`（AGENTS.md §2），契约由
`Tests/Mud.Wechat.OpenPlatform.Tests` 的官方路径 / 字段名逐字比对锁定。
