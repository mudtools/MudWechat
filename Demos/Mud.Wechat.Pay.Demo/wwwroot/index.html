微信支付 APIv3 Demo（DM-06）

本页面只做一件事：把「下单 → 通知 → 查单 → 关单 → 退款」这条链上的每个 SDK 调用点摊开， 并把官方应答原样回显，方便看清哪些字段才是权威。

三条硬约束
  1. 下单 / 关单 / 退款是真实出资动作 ⇒ 需 MUDWECHAT_DEMO_ALLOW_WRITE=1；未开启时这些路由根本没有映射（404，而不是 403）。
  2. notify_url 必须是公网 HTTPS 且与回调路由 /pay/{商户号} 逐字一致。本机地址下得出单、收不到通知 ⇒ 表现为「手机端支付成功，但台账一动不动」。
  3. 支付成功的权威判定只看查单或 TRANSACTION.SUCCESS 通知，不看手机端回调。

⑦ 回调路由

APIv3 通知统一打到 POST /pay/{商户号}；未在商户表登记的键会被 fail-closed 拒绝，绝不回落默认商户。 三道闸顺序固定：平台证书验签 → 时间窗 → 一次性指纹（解密成功后才消费）。 验签依赖已下载的平台证书，故本 Demo 不内置 Pay 回调离线自测（需真实商户签名，见规划方案 R-3）。
