# 文档根

各项目的 SDK 开发文档集中在此。**规范只有一份，项目各自落一层目录。**

## 结构

```
Documents/
  _spec/                       # 规范与模板（项目无关，改这里影响全部项目）
    文档编写规范.md
    模板/接口族文档.md
  <项目名>/                     # 每个项目一层
    README.md                  # 项目文档索引 + 覆盖进度表
    guide/                     # 接入指南
    reference/                 # 接口参考（路径与源码目录逐段映射）
    appendix/                  # 附录（错误码、术语、频率上限）
```

## 新项目接入

1. 读本项目的 [文档编写规范](./_spec/文档编写规范.md)，**不要**复制一份到项目内改——规范是单一来源。
2. 建 `<项目名>/README.md`：产品线或模块地图 + 覆盖进度表 + 从哪读起。
3. 定 `reference/` 与源码目录的映射规则，写进项目 README（规范 §2.1 给了多产品线共仓与单产品线两种基线形态）。
4. 先用一个**端点数少、有代表性**的接口族写出 L3 样版，评审通过后再批量推进。
5. 进度表只统计 `已核验`，不统计写过的文件数。

样版参考：[Mud.Wechat/reference/Work/AccountId/Bot.md](./Mud.Wechat/reference/Work/AccountId/Bot.md)（单端点接口族，含取证留痕、易混对照、已知留档缺口的完整写法）。
